# HamHaeVoca | 함해보카

**내 단어장으로 공부하는 Android 영어 어휘 학습 앱**

HamHaeVoca는 직접 만든 단어장을 불러와 관리하고, **낱말카드·시험·맞추기**로 반복 학습하는 Android 앱입니다. 폴더별 정리, 암기/미암기 상태, 정답·오답 기록, 예문 포함 단어장을 지원하도록 개발하고 있습니다.

> **개발 상태 — 기능 개선 및 안정화 중**  
> 이 문서는 제공된 `src.zip`, 이후 제공된 기능별 수정 패치, 개발 요구사항을 토대로 작성했습니다. **GitHub 기본 브랜치와 모든 패치가 동일하다고 보장하지 않으며**, 전체 Gradle 빌드·실기기 동작 검증도 완료된 상태로 표시하지 않습니다.

## 주요 기능

| 구분 | 기능 |
| --- | --- |
| 단어장 관리 | 생성·가져오기·갱신, 검색, 이름순/역순/최근 수정순 정렬 |
| 폴더 관리 | 폴더 생성·이름 변경·삭제, 단어장 이동, 폴더별 단어장 개수 표시 |
| 일괄 작업 | 단어장 다중 선택, 폴더로 이동, 삭제 확인 후 일괄 삭제 |
| 단어 목록 | 단어·뜻·품사 등 확인, 암기/미암기 상태 관리, 오답 기반 필터 |
| 낱말카드 | 양방향 카드 학습, 스와이프, 암기 상태 기록, 정답 공개 후 예문 표시 |
| 시험 | 영어→한국어, 한국어→영어, 혼합, 품사 선택 등의 출제 방식 및 시험 결과 |
| 맞추기 | 사용 단어 수·제한 시간 설정, 맞추기 진행·결과 확인 |
| 데이터 | SQLite 기반 단어장·학습 상태·정답/오답 기록 관리 |
| UI 언어 | 한국어·영어·프랑스어·스페인어·베트남어·일본어·중국어 간체 |

**단어장 내용은 자동 번역하지 않습니다.** 언어 설정은 앱의 제목·버튼·메뉴·메시지 등 UI에만 적용하며, 가져온 `Vocabulary`, `Mean`, `Example`은 원문 그대로 유지합니다.

## 시작하기

1. [GitHub 저장소](https://github.com/sosomeet/HamHaeVoca)를 복제하거나 Android Studio로 프로젝트를 엽니다.
2. Android SDK 및 프로젝트의 Gradle 구성을 확인하고 동기화합니다.
3. 앱을 빌드하여 에뮬레이터 또는 기기에 설치합니다.
4. CSV/TSV/XLSX 파일을 선택해 단어장을 생성합니다.
5. 단어장을 열어 **낱말카드**, **시험**, **맞추기**를 사용합니다.

> APK 배포·릴리스와 빌드 성공 여부는 저장소의 실제 상태를 확인하세요. `src.zip`은 Android Studio의 전체 프로젝트(Gradle 래퍼 등)를 대체하지 않습니다.

## 단어장 파일 형식

첫 행을 헤더로 사용하는 다음 두 형식을 지원하도록 설계했습니다.

**4열 — 기본 단어장**

| Vocabulary | Mean | Day | Category |
| --- | --- | --- | --- |
| apple | 사과 | 1 | noun |

**5열 — 예문 단어장**

| Vocabulary | Mean | Day | Category | Example |
| --- | --- | --- | --- | --- |
| although | 비록 ~일지라도 | 1 | conjunction | Although it rained, we went out. |

- `Example` 열은 **선택 사항**입니다. 비어 있거나 없는 경우 해당 예문 영역을 표시하지 않습니다.
- 예문이 있으면 가져오기 미리보기와 낱말카드의 정답 확인 후 화면에서 활용합니다.
- 가져오기 미리보기의 인덱스는 Excel 행 번호가 아닌 **첫 단어 1번**부터 시작합니다.
- 갱신 시 기존 암기 상태·정답·오답 횟수 보존이 요구됩니다. 실제 갱신 시나리오별 보존 결과는 검증이 필요합니다.
- 최근 UI 개편에서는 **직접 내용 입력**과 **구분자 선택(자동)** 화면 요소를 제거하고 파일 가져오기 방식을 유지했습니다. CSV/TSV 자동 판별 기능은 내부적으로 유지하도록 수정했습니다.

## IA · 화면 구조

**IA ID**는 화면을 정확하게 식별하기 위한 개발용 이름입니다. 실제 화면에 ID를 표시하거나 Java/XML 파일명을 바꾸지 않습니다. 동일 Activity 안의 메뉴·선택 모드·설정 팝업도 별도 UI 상태로 식별합니다.

```text
HOME-01  메인 화면
├─ HOME-02    사이드 메뉴 (햄버거)
├─ HOME-03    폴더 관리
├─ HOME-04    단어장 다중 선택 모드
├─ IMPORT-01  단어장 생성·가져오기
├─ BOOK-01    단어장 상세 화면
│  ├─ BOOK-02   단어장 설정
│  ├─ BOOK-03   단어 추가·편집
│  ├─ STUDY-01  낱말카드
│  ├─ STUDY-02  낱말카드 설정
│  ├─ QUIZ-01   시험 설정
│  │  ├─ QUIZ-02  객관식 시험
│  │  ├─ QUIZ-03  품사 시험
│  │  └─ QUIZ-04  시험 결과
│  └─ MATCH-01  맞추기 설정
│     ├─ MATCH-02 맞추기 진행
│     └─ MATCH-03 맞추기 결과
└─ IMPORT-02  기존 단어장 갱신 (IMPORT-01과 Activity 공유)
```

## UI 설계 원칙

- **기존 HamHaeVoca 스타일 유지:** 삼성 노트는 사이드 메뉴의 조작 흐름을 참고할 뿐, 앱 카드 디자인을 복제하지 않습니다.
- **아이콘 최소화:** 일반 버튼은 텍스트 중심으로 통일합니다. 햄버거·검색·추가 및 명시적으로 지정된 선택 툴바 아이콘만 예외입니다.
- **목록과 상단 UI 여백 분리:** 메인 단어장 목록 및 `BOOK-01-G`에 필요한 좌우 여백을 적용하면서 상단 UI 배치는 기존 기준을 유지합니다.
- **선택 상태 시각화:** 선택한 단어장에 민트색 **단일 테두리**를 적용하도록 수정했습니다.
- **사이드 메뉴:** 폴더별 단어장 수를 숫자로 표시하고, 현재 정렬·언어 설정값을 함께 표시하도록 개선했습니다.
- **용어 통일:** 한국어 UI의 ‘외움’은 **암기**, ‘못 외움’은 **미암기**로 변경했습니다. DB 내부 상태 구분은 유지합니다.
- **다국어:** UI 신규 문자열을 추가하면 지원 언어 리소스의 키와 번역을 함께 관리합니다.

## 데이터 보존 및 개발 규칙

1. **사용자 데이터 우선:** 단어장, 폴더, 암기 상태, 정답·오답 횟수 등 SQLite 데이터를 임의 초기화하지 않습니다.
2. **갱신 호환성:** Excel 가져오기/갱신, 기존 4열 단어장, 선택적 5열 예문 단어장을 모두 고려합니다.
3. **UI 범위 최소화:** 요청한 IA 화면과 요소만 수정하며 관련 없는 화면·아이콘을 변경하지 않습니다.
4. **로컬라이제이션:** 문자열을 변경하면 7개 언어의 화면 표시 및 리소스 누락 여부를 검사합니다.
5. **패치 배포:** 수정된 **완전한 파일만** `src/main/...` 상대 경로를 유지한 ZIP으로 제공합니다. ZIP의 `src/`는 프로젝트의 `app/src/`에 대응합니다.
6. **패치 충돌 예방:** 누적 패치가 서로 같은 파일을 수정할 수 있으므로 **최신 프로젝트 소스**를 기준으로 병합한 후 배포합니다. 과거 패치를 순서 없이 덮어쓰지 않습니다.
7. **검증 단계 분리:** XML 정적 검사, Java 컴파일, Gradle 전체 빌드, 실기기 테스트를 서로 다른 검증 단계로 기록합니다.

> **주의:** 단어장 다중 삭제는 해당 단어장과 연결된 학습 기록에도 영향을 줄 수 있습니다. 사용자가 확인한 이후에만 삭제해야 하며, 실기기에서 삭제·복원 불가 안내 및 영향 범위를 검증해야 합니다.
